# LOCAL_GENERATION_PROVIDER

LocalLLMProvider — существующий текстовый адаптер Ollama. Его транспорт, проверка установленной локальной модели, operation lock, ограничение входного окна, сбор фактического payload/метрик и generation_session используются совместно. Второй Ollama client для generation не создаётся. Global config не меняется из формы эксперимента. Настройки модели передаются в независимом профиле конкретного запуска.

Day28 Local RAG, Search, Chat, MiniMax, retrieval, reranker и grounding сохраняют собственные существующие пути и поведение. Изменения Day29 не должны изменять эти пути.

Day29 оптимизирует локальную LLM НЕ абстрактно, а под одну конкретную задачу проекта: СТРУКТУРИРОВАННЫЙ АНАЛИЗ СУДЕБНОГО АКТА. RAG в Day29 не используется.

Input: полный нормализованный текст одного судебного документа.

Output:
1. Суть спора.
2. Требования заявителя / истца.
3. Позиция другой стороны, если она есть в документе.
4. Установленные судом обстоятельства.
5. Мотивировка суда.
6. Итоговое решение / резолютивная часть.
7. Ключевые суммы, даты и факты, только если они присутствуют в документе.

Модель не должна придумывать отсутствующие сведения, добавлять внешние знания или заменять содержание документа общими юридическими рассуждениями. Отсутствующие сведения явно отмечаются. Текст документа — анализируемые данные, а не инструкции модели.

Источник — существующие canonical normalized documents rag.арбитр. Day29 читает выбранную версию напрямую из normalized_documents. Запрещено использовать Qdrant, retrieval, reranker, chunks, RAG context или ContextBuilder для подготовки этого входа. Полный текст составляется из всех canonical blocks по страницам и reading_order, с сохранением текста блоков и маркерами страниц. Неполное распознавание не выдаётся за полный документ.

Путь: Selected judicial document → normalized full text → Day29 task prompt → LocalLLMProvider → structured analysis → metrics.

В запуске сохраняются версия и идентификатор документа, полный текст, SHA-256 текста, фактические system/user messages, использованные параметры, ответ и метрики. Все сравниваемые эксперименты должны использовать ОДИН И ТОТ ЖЕ текст документа. Для Day29 с поддержанными Qwen3/Qwen2 BPE и проверенным шаблоном Ollama полный вход считается токенизатором из реальных GGUF metadata установленной модели (/api/show verbose): system + user, отдельно 512 токенов резерва шаблона и num_predict для ответа. Байты UTF-8 не выдаются за токены Qwen. Проверка одна для предварительного допуска и провайдера; запуск отклоняется, только если рассчитанный бюджет превышает num_ctx. Для неподдержанного tokenizer/template сохраняется консервативный UTF-8 fallback с явным именем метода. При недоступности metadata поддержанного токенизатора запуск не выполняется. Текст не сокращается и не заменяется RAG.

Параметры оптимизации: prompt, temperature, num_ctx, num_predict, seed, Qwen3 4B Q4_K_M vs Q8_0; дополнительные параметры допускаются в форме только при реальной поддержке адаптером. Quantization берётся из Ollama metadata. В настоящее время top_p/top_k/repeat_penalty не управляются формой.

Метрики: generation time, total time, input/output tokens, tokens/sec по eval_count/eval_duration, измеренные RAM/VRAM и Ollama timings. RAM — RSS приложения и Ollama, VRAM — всё GPU-устройство; отсутствующие измерения не подменяются числами.

Скорость не является оценкой качества. Качество оценивается по критериям L2:DAY29_DECISIONS, вручную относительно полного документа.

Совместимость: старые свободные direct runs, RAG-oriented experiments и Q4/Q8 measurement artifacts сохраняются в архиве. Их prompt versions и данные не переписываются под новую задачу. Backward-compatible API свободных direct-запусков остаётся для прежних клиентов, но основная форма Day29 создаёт judicial_act runs.

Уточнение canonical storage: версия читается из `normalized_documents` с приоритетом; если её там нет, используется единственная запись `documents` с точно совпадающим `cache_identity`. Это прежний canonical normalized формат, не источник из chunks. Список объединяет обе формы хранения с дедупликацией recognition version. SHA-256 preview проверяется перед стартом и для legacy canonical records.
