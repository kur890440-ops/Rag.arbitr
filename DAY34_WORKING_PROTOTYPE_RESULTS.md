# Day34 — работающий прототип: протокол проверки

Статус: **IN PROGRESS / НЕ ПРИНЯТО**. Этот файл обновляется по результатам реальных проверок. Создание файла, HTTP 200 и успешные unit tests по отдельности не являются приёмкой.

## Границы

Работа ведётся в изолированных копиях SQLite, Qdrant и web data под `.runtime/day34p/`. Production `.env` и `config.toml` не изменяются; production-сервис не перезапускается. Новые зависимости не добавлены. Для SMB разрешена только новая тестовая подпапка внутри `\\192.168.37.25\temp\!\1\1`.

## Изменённые компоненты

- `application/consult.py`, `storage.py`, `llm.py`: журнал резервов, однократное списание/возврат, сохранение неизвестного исхода; явная внутренняя тестовая политика без накопительного тестового лимита токенов.
- `application/provider_failures.py`, `application/exhaustive.py`, `application/evidence_review.py`, `application/dialogue.py`: категории отказов, диагностика пакетов, ограниченное восстановление обрезанного ответа, сохранение неизвестных полей условия без выдуманного периода.
- `application/document_workspace.py`, `application/workspace_protocol.py`, `config.py`: чтение найденных закреплённых версий, содержимое анализа для Planner, извлечение сторон существующим механизмом, сохранение состояния отмены и счётчиков, ограниченные длительность/параллелизм/число операций.
- `application/workspace_validation.py`: обход всех блоков, неизменяемые проверяемые фрагменты, составные канонические цитаты, отдельная точная проверка приложения с цитатами, повторное использование проверок неизменённых блоков при совпадении источников и политики проверки.
- `application/chat.py`, `application/dialogue.py`: передача проверенного набора документов в существующий WorkingContext/ReferenceResolver; сравнительный intent не может сузить исполнение до Point RAG; существующий exhaustive-путь публикует проверенные факты и цитаты.
- Регрессионные тесты и изолированные E2E-сценарии в `.runtime/day34p_*.py`.

## Учёт провайдера

Резерв имеет состояния `RESERVED`, `SENT`, `SETTLED`, `NOT_SENT`, `UNKNOWN_OUTCOME`. Только положительное доказательство отсутствия отправки разрешает возврат. Завершённый расчёт и возврат идемпотентны, в том числе при конкурентных вызовах. При неизвестном исходе резерв сохраняется. Исторический расход не пересчитывается предположениями.

`workspace.prototype_unmetered` по умолчанию выключен. Внутренний стенд включает его только в объекте конфигурации процесса. Клиентская проверка дневного лимита сохраняется. Ограничения входа, API, времени, числа вызовов, попыток и параллелизма остаются. Фактические reported usage сохраняются; незавершённый вызов не объявляется бесплатным.

## Установленные причины отказов

1. Старый тестовый byte-reservation ограничитель блокировал отправку ещё до MiniMax. В новом стенде накопительный искусственный потолок удалён; реальные ограничения запросов сохранены.
2. Planner вызывал анализ найденного набора до чтения всех выбранных файлов. Backend дочитывает только документы из проверенного результата поиска, с проверкой текущего разрешения и версии.
3. Большие ответы извлечения/проверки обрезались. Файловое извлечение ограничивает пакет 32 исходными блоками, сохраняет все блоки и использует два существующих рабочих потока. Проверка обрезанного пакета имеет ограниченное деление, без повторения успешных пакетов.
4. `condition.period=null` приводил к потере всего факта. Неизвестный период сохраняется, но такой факт не участвует в сравнении сроков.
5. Planner получал только статус анализа и расширял поиск вместо создания файла. Теперь получает ограниченную содержательную сводку и инструкцию завершать документ с явными ограничениями.
6. Проверяющая модель копировала служебные поля или перефразировала текст DOCX. Проверяемый текст теперь формирует backend из неизменяемых фрагментов; модель возвращает только решения и смысловые поля.
7. Отдельные абзацы не позволяли подтвердить связь имени и роли. Валидация использует существующие составные цитаты с точными координатами; не превращает разрозненные абзацы в непрерывную цитату.
8. Router одновременно возвращал `COMPARISON` и `POINT_RAG`. Исполнительный охват определяется заявленной типизированной семантикой: сравнение требует полного просмотра текущего разрешённого набора, без расширения за его пределы.
9. Копирование тестовых БД накапливало активные ADMIN-сессии до штатного лимита. Только в новой изолированной копии старые тестовые сессии отзываются существующим ADMIN-механизмом. Production-лимит не изменён.

## Предыдущие реальные проверки — не окончательная приёмка

Реальный MiniMax создал DOCX по пяти договорам и новую редакцию с разделом различий. Проверены скачивание, ZIP/OOXML, наличие заголовков/таблиц, неизменность исходной редакции и остальных частей OOXML-пакета. Содержательная проверка этой ранней версии не завершилась; файлы имели статус UNVERIFIED. Этот результат не объявляется готовым прототипом.

Извлечение сторон установило пять контрагентов. Для части договоров дата не была подтверждена; она не подставлялась из имени файла. Отказы дальнейших стадий используются для исправлений и повторных проверок.

## Диагностика и ограничения

Общие диагностические события не содержат секретов или полных договоров. Полные запросы/ответы для разрешённой проверки сохраняются отдельно в локальных private-артефактах стенда. Семантическая оценка остаётся вероятностной: неподтверждённые положения получают UNVERIFIED, а не автоматически VERIFIED. Полнота обхода и подтверждённость содержания учитываются отдельно.

Браузерных инструментов в сессии не обнаружено. Проверки через TestClient используют реальные HTTP-маршруты приложения, настоящие workers и MiniMax; визуальная проверка браузером не заявляется.

## Внедрение и rollback

До завершения приёмки внедрение не рекомендуется. После PASS: сохранить согласованный commit/patch, сделать резервную копию production SQLite/Qdrant/web data и конфигурации, выполнить миграцию добавления журнала резервов на копии, затем запросить отдельное разрешение на остановку/обновление production. Не переносить тестовый `prototype_unmetered=True`, тестовые сессии и источники. После запуска проверить авторизацию, ACL, обычный Chat, /consult, индексацию и журнал usage. Для rollback остановить новую версию по отдельному разрешению, восстановить прежний код и согласованную резервную копию данных; не удалять SMB-файлы автоматически. Опубликованные версии обрабатывать отдельным проверяемым действием.
