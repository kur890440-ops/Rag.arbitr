# Day33 — исправление внутреннего консультанта

Статус: исправления внесены и загружены в localhost-сервер. Основной document E2E успешен. Пользователь разрешил лимит 1 200 000; он применён. Финальный live-контроль смены темы и возврата к договору успешно завершён в работающем /consult через Edge и MiniMax.

## Установленные причины

1. `ConsultService` использовал `PublicKnowledge`: без записей PUBLIC scope был пуст, независимо от готовности документов Day31.
2. В `ConsultIntent` отсутствовал ARCHIVE. Вопросы о составе базы могли попадать в генерацию общего ответа.
3. Адаптер вызывал `RAGComparisonService.prepare` с BASELINE по умолчанию. В live диагностике найдено 7 кандидатов, но отсутствовал reranking. Лимит контекста 8000 байт не вмещал один из релевантных фрагментов размером 8271 байт.
4. После включения reranker один live ответ превысил существующий лимит вывода MiniMax 4096 токенов (`TRUNCATED/OUTPUT_LIMIT`). Это зафиксированный неуспешный прогон, а не успешный E2E.

## Реализация

- `/consult` использует `InternalKnowledge`: существующий динамический `ResultsService.chat_snapshot`, активные сетевые версии и готовые ручные корпуса. Проверяются committed index runs, chunks, canonical recognition SUCCESS и права на источники. Новый индекс не создаётся.
- Политика ограничена консультантом. PUBLIC/PRIVATE и интерфейс публикации не изменяют эту область; глобальные публикационные записи не изменялись.
- ARCHIVE классифицируется существующим семантическим router; все сведения ответа строятся программой из Document/Source Registry. Форматы, источники, INDEXED, даты появления, количество; максимум 12 строк. Неизвестная дата явно обозначается. Подстрока имени ищется от границы слова, чтобы «агентск» не включало «субагентск».
- DOCUMENT: существующие RetrievalPolicy, Qdrant hard scope до candidate limit, QueryRewriter/REWRITE_RERANK, BGE reranker, ContextBuilder, MiniMax и grounding. Лимит контекста до 12000 байт в рамках существующего admission budget. Полный обзор использует существующий Exhaustive.
- GENERAL не вызывает retrieval. MIXED отделяет общее объяснение и подтверждённые положения документов.
- Используются существующие ChatSession, DialogueWorkingContext, WorkingContextService и ReferenceResolver. Текущий самостоятельный вопрос сначала классифицируется без старых фактов; для не-GENERAL подключается история. ReferenceResolver работает только для DOCUMENT/MIXED и дополняет неразрешённую реплику, не подменяя уже разрешённый текущий вопрос. История передаёт названия процитированных документов; новая система памяти не создаётся. При нескольких подходящих договорах требуется уточнение, если не запрошено сравнение.
- DOC/DOCX citations показывают раздел/структурный блок без выдуманных страниц; PDF сохраняет страницу. Quote и ссылка принадлежат текущей сессии, доступ повторно проверяется.

## Сеть

- По умолчанию `consult.allowed_networks = ["127.0.0.0/8", "::1/128"]`. Допустимы явно указанные частные LAN/VPN CIDR; wildcard 0/0 запрещён.
- Проверяется непосредственный адрес клиента. Forwarded и X-Forwarded-* не принимаются. CLI запускает uvicorn с `proxy_headers=False`.
- Внешняя публикация не выполнялась. Фактический listener: `127.0.0.1:8765`; TCP к `192.168.11.41:8765` не подключился.
- Caddy/nginx/Apache не обнаружены; Windows portproxy пуст, W3SVC не найден. Firewall Domain/Private/Public включены. Правила маршрутизатора/удалённой VPN и внешнее интернет-сканирование не проверялись.
- LAN/VPN разрешения проверены через ASGI-тест адресов; настоящая удалённая VPN-сессия не проверялась. Для фактического LAN развёртывания нужна конкретная разрешённая подсеть и отдельный listener; сейчас сервис намеренно остаётся localhost.
- `/chat`, `/sources`, `/publications`, `/api/runs` остаются недоступны клиентам LAN. Factory `create_public_app` сохраняется как совместимое имя ограниченного listener без административных маршрутов.

## Реальный MiniMax и браузер

Использованы настоящий работающий сервер, реальные индексированные документы и MiniMax. Все промежуточные неуспешные результаты сохранены отдельно и не засчитываются как успех.

1. «Какие документы у тебя есть?» — реестровая сводка: 38 документов; 29 DOC, 7 DOCX, 2 PDF. Первые 12 строк.
2. «Есть ли у тебя агентские договоры?» — 6 совпадений имени; субагентские договоры после исправления границы слова не смешиваются с агентскими.
3. «Какие обязанности предусмотрены одним из этих договоров?» — запрос уточнения названия, без произвольного выбора.
4. После выбора договора Леднева — три обязанности: поиск клиентов; информирование страхователей; ведение учёта. В финальном браузерном прогоне 3 цитаты, HTTP 200 для всех ссылок, 64.27 s.
5. «А какие сроки отчётности?» — не позднее 10 дней после окончания каждого календарного месяца. Тот же договор, 1 цитата, HTTP 200, 44.42 s.
6. Независимый GENERAL про страховую премию успешно проверен реальным MiniMax без RAG. Однако GENERAL после вопроса об отчётности в браузере ошибочно продолжил тему договора. Исправление: первичная классификация самостоятельного вопроса без прежних фактов; история подключается только для не-GENERAL; ReferenceResolver не вызывается для GENERAL. После разрешённого увеличения квоты финальная браузерная проверка успешна: после вопроса об отчётности получено именно общее определение страховой премии, без цитат и без продолжения темы отчётности (13.53 s).
7. Возврат к договору и MIXED были выполнены real MiniMax до последнего изменения query rewrite: режимы распознаны, но конкретный ответ тогда не прошёл retrieval. Эти ранние результаты не засчитываются как успешные. Возврат к договору после последнего исправления отдельно подтверждён финальным браузерным прогоном (73.41 s, три обязанности, три цитаты из того же договора). MIXED проверен автоматическими тестами; новый успешный live MIXED после последнего исправления отдельно не заявляется.

Четыре цитаты из успешных ответов про обязанности/отчётность независимо сверены с существующими canonical document_blocks. Все точные; DOC отображает блоки, а не страницы. Проверено **0 PUBLIC grants** после тестов.

Edge: интерфейс показан на desktop и mobile; screenshot mobile осмотрен. Ошибок JavaScript нет, горизонтального переполнения при ширине 390 px нет. Проверена отправка HTMX без перезагрузки, отображение ответов и ссылки источников. В последнем браузерном прогоне проверены и смена темы, и возврат к договору; desktop screenshot осмотрен.
