@PROJECT:rag.арбитр

@L3:DAY31_CHAT_UX_REDESIGN
@PRESERVE

ЗАДАЧА

Выполнить полноценный UX-рефакторинг
существующего Chat.

Текущая проблема:

- три постоянно открытые колонки;
- несколько независимых прокруток;
- громоздкие карточки сообщений;
- технические данные занимают много места;
- диалог не является главным элементом.

Нужно исправить именно layout и UX.

==================================================
1. INSPECT FIRST
==================================================

Изучи:

- существующие Chat templates;
- общий layout/navigation;
- CSS;
- HTMX/SSE;
- ChatSession UI;
- source selector;
- document selection;
- Task Memory;
- message rendering;
- citations/source navigation;
- diagnostics;
- scrolling;
- responsive behavior.

Переиспользовать существующие компоненты.

Не создавать параллельные реализации.

==================================================
2. NEW CHAT LAYOUT
==================================================

Структура:

┌─────────────────────────────────────┐
│ Название чата                       │
│ Область анализа · Документы         │
│ История · Память                    │
├─────────────────────────────────────┤
│                                     │
│            ДИАЛОГ                   │
│                                     │
│ Пользователь                        │
│ Ассистент                           │
│ Источники                           │
│                                     │
├─────────────────────────────────────┤
│ Сообщение                           │
│                            Отправить│
└─────────────────────────────────────┘

Главная область должна занимать
почти всю доступную ширину.

Для текста установить комфортную
максимальную ширину строк,
а не растягивать абзацы
на огромный монитор.

==================================================
3. CHAT HISTORY DRAWER
==================================================

Историю чатов перенести
в выдвижную левую панель.

По умолчанию закрыта.

Внутри:

- Новый чат;
- список предыдущих чатов;
- даты;
- выбор чата.

Панель должна закрываться:

- по кнопке;
- по Escape;
- после выбора чата на мобильном экране.

Не менять существующее хранение истории.

==================================================
4. TASK MEMORY DRAWER
==================================================

Память задачи перенести
в выдвижную правую панель.

Открывается кнопкой:

[Память задачи]

Внутри сохранить:

- цель;
- ограничения;
- уточнения;
- термины;
- открытые вопросы;
- существующие действия редактирования.

Не изменять модель Task Memory.

Закрытая панель
не занимает место в layout.

==================================================
5. MESSAGE DESIGN
==================================================

USER:

- компактное сообщение справа;
- спокойный фон;
- без больших технических подписей.

ASSISTANT:

- слева;
- основное содержание без громоздкой рамки;
- нормальное форматирование Markdown;
- корректные списки и таблицы;
- читаемые длинные ответы.

Не помещать весь ответ
в textarea или scrollable card.

==================================================
6. SOURCES / CITATIONS
==================================================

Под ответом ассистента:

[Источники · N]

При раскрытии:

- документ;
- страница или DOCX block;
- подтверждающая цитата;
- переход к документу.

Inline citations в тексте сохранить.

Не прятать сами цитаты так,
чтобы ссылки перестали работать.

==================================================
7. DIAGNOSTICS
==================================================

Техническую информацию убрать
из основного текста диалога.

Под ответом:

[Диагностика]

При раскрытии:

- RAG mode;
- timings;
- retrieval statistics;
- grounding;
- repair;
- другие существующие показатели.

Использовать existing diagnostic data.

Не добавлять новые вычисления RAG
ради изменения UI.

==================================================
8. SOURCE SELECTOR
==================================================

В header Chat оставить:

Область анализа:
[Все документы ▼]

И кнопку:

[Выбрать документы]

Показывать выбранную область
компактно.

Например:

"Все документы"

"Источник: Доки"

"Выбрано: 3 документа"

Не показывать таблицу файлов
в основном Chat.

==================================================
9. DOCUMENT SELECTION DRAWER
==================================================

Использовать существующий
document selection mechanism.

Открывать по кнопке.

Поддержать:

- выбор одного документа;
- множественный выбор;
- выбор источника;
- сброс выбора;
- применение.

Сохранять существующий scope
в ChatSession.

Не менять retrieval filtering semantics.

==================================================
10. INPUT COMPOSER
==================================================

Поле ввода закрепить
внизу рабочей области.

Оно должно быть доступно
при длинном диалоге.

Поддержать:

Enter — отправить.

Shift+Enter — новая строка.

При отправке:

- исключить случайное дублирование;
- показать состояние выполнения;
- не терять введённый текст при ошибке.

Использовать существующий
request submission mechanism.

==================================================
11. SCROLL BEHAVIOR
==================================================

В центральном Chat
должна быть одна основная прокрутка.

Новые сообщения:

если пользователь находится внизу —
прокрутить к новому сообщению.

Если пользователь читает старые сообщения —
не перемещать его принудительно.

Показать компактную кнопку:

[К новым сообщениям]

При переключении чатов
сохранять разумное поведение позиции.

==================================================
12. RESPONSIVE
==================================================

Desktop:
широкий центральный Chat.

Tablet:
тот же Chat, компактный header.

Mobile:
диалог на всю ширину;
история и память открываются поверх.

Никаких постоянных боковых колонок
на узких экранах.

==================================================
13. VISUAL CONSISTENCY
==================================================

Сохранить существующую
цветовую схему rag.арбитр.

Упростить:

- рамки;
- отступы;
- заголовки;
- технические подписи.

Использовать единые CSS components.

Не добавлять React/Vue
или другой frontend framework.

Не дублировать CSS правила
для одинаковых элементов.

==================================================
14. PERFORMANCE
==================================================

Не загружать всю историю сообщений
при наличии большого чата.

Переиспользовать existing pagination,
если она реализована.

Если нет — выбрать минимальное
совместимое решение
без переписывания backend.

Не допускать постоянного
полного перерисовывания Chat
при появлении нового сообщения.

==================================================
15. PRESERVE FUNCTIONALITY
==================================================

Обязательно сохранить:

- создание/переключение чатов;
- ChatSession;
- Task Memory;
- выбор документов;
- source scope;
- /help;
- Point RAG;
- Exhaustive;
- follow-up;
- citations;
- grounding;
- diagnostic export.

Никаких изменений
бизнес-логики анализа документов.

H. Citation navigation работает.

Запустить существующий test suite.

==================================================
17. VISUAL VERIFICATION
==================================================

КРИТИЧЕСКИ:

Не ограничиваться HTML unit tests.

Открыть реальную страницу
в браузере, если доступны
подходящие browser/UI tools.

Проверить:

- desktop layout;
- mobile layout;
- длинный диалог;
- длинный ответ;
- открытие drawers;

- выбор документов;

==================================================
18. ACCEPTANCE
==================================================

Готово, когда:

1. Chat выглядит как современный
   диалоговый интерфейс.

2. История не занимает
   постоянную левую колонку.

3. Память не занимает
   постоянную правую колонку.

4. Основной экран сосредоточен
   на сообщениях.

5. Нет лишних вложенных scrollbars.

6. Ответы читаются полностью.

7. Источники и diagnostics
   доступны по раскрытию.

8. Поле ввода всегда доступно.

9. Выбор документов
   работает как раньше.

10. RAG/Chat backend не изменен.
