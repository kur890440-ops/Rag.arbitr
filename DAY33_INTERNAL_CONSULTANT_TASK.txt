ЗАДАЧА

Исправить существующий /consult.

Сейчас консультант MiniMax
на вопрос о загруженных документах
отвечает:

"Документы в этот чат не загружались".

Это неверное поведение.

Документы уже загружены
и проиндексированы через Day31.

Консультант должен использовать
эту базу знаний автоматически.

==================================================
1. ОБЯЗАТЕЛЬНЫЙ СЦЕНАРИЙ
==================================================

Пользователь открывает /consult.

Спрашивает:

"Какие документы у тебя есть?"

Система получает реальные документы
из существующего Document Registry
и сообщает их состав.

Пользователь спрашивает:

"Что предусмотрено агентским договором?"

Система выполняет существующий RAG,
передает найденные фрагменты MiniMax
и возвращает ответ с цитатами.

Пользователь спрашивает:

"А какие у агента обязанности?"

Ассистент продолжает обсуждение
того же договора.

Не требуется загружать документы
в сам Chat или выбирать PUBLIC.

==================================================
2. INSPECT FIRST
==================================================

Изучи:

- существующий /consult;
- Day33 routing;
- PUBLIC/PRIVATE filtering;
- Document Registry;
- canonical document storage;
- Day31 source scope;
- ChatSession;
- ReferenceResolver;
- RetrievalPolicy;
- Point RAG;
- Exhaustive;
- MiniMax provider;
- grounding/citations.

Найди фактическую причину,
почему /consult не использует
существующий корпус документов.

Не ограничивайся изменением
system prompt.

==================================================
3. INTERNAL KNOWLEDGE
==================================================

Для /consult использовать
все документы, действительно
готовые к поиску в существующем
активном индексе.

Не требовать PUBLIC-флагов.

Не изменять документы или их
глобальные права публикации.

Изменение ограничить
политикой доступа /consult.

Новые INDEXED документы
должны автоматически входить
в доступную область поиска.

Не создавать второй индекс.

==================================================
4. INTERNAL NETWORK ACCESS
==================================================

/consult работает без авторизации.

Поэтому обязательное условие:

доступ только через разрешенную
LAN/VPN-сеть.

Проверить:

- bind address;
- reverse proxy;
- trusted proxy headers;
- firewall/access policy;
- отсутствие внешнего доступа.

Не доверять произвольному
X-Forwarded-For от клиента.

Если ограничение доступа
не настроено надежно,
не публиковать сервис наружу.

Не открывать для внешних клиентов
внутренний Chat, Sources, MCP
или административные API.

==================================================
5. ARCHIVE QUESTIONS
==================================================

Добавить/исправить маршрут:

ARCHIVE.

Он читает:

- список документов;
- названия;
- источники;
- форматы;
- статусы индексации;
- даты появления;
- количество документов.

Использовать существующий
Document Registry / Source Registry.

Не использовать LLM
для выдумывания этих сведений.

Если документов много,
давать краткую сводку
и ограниченный список,
не перегружая ответ.

==================================================
6. DOCUMENT QUESTIONS
==================================================

Для вопросов о содержимом:

/consult
→ existing RetrievalPolicy
→ Qdrant
→ reranker
→ ContextBuilder
→ MiniMax
→ existing Grounding/Citations.

Не создавать отдельный RAG.

Не искать только в документах,
прикрепленных к текущему сообщению.

Использовать существующий корпус.

==================================================
7. GENERAL AND MIXED
==================================================

Сохранить:

GENERAL:
MiniMax отвечает по общим вопросам.

MIXED:
MiniMax объясняет понятие,
а конкретные условия подтверждает
содержимым документов.

Четко отделять общие знания
от положений конкретного договора.

==================================================
8. CONVERSATION QUALITY
==================================================

Проверить и исправить:

- понимание уточнений;
- сохранение темы;
- смену темы;
- возвращение к предыдущей теме;
- использование ранее найденных
  подтвержденных референтов.

Пример:

Q1:
"Какие агентские договоры есть?"

Q2:
"Какие у агента обязанности?"

Q3:
"А когда он должен сдавать отчет?"

Ассистент должен понимать
связь вопросов.

При нескольких подходящих договорах
не угадывать нужный:
уточнять или сравнивать
с явным указанием документов.

Не создавать вторую систему памяти.

==================================================
9. SOURCE GROUNDING
==================================================

Каждый вывод о договоре
подтверждать документом и цитатой.

Для PDF:
страница.

Для DOC/DOCX:
структурный блок/раздел,
если реальные страницы неизвестны.

Не придумывать реквизиты,
условия или цитаты.

При недостаточности документов
давать честный частичный ответ
или уточнение.
