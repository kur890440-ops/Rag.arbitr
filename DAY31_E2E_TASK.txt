ЗАДАЧА

Доработать реализованный Day31:

1. Подключить настоящую сетевую папку.
2. Исправить UNSUPPORTED_FORMAT для DOCX.
3. Провести полноценный E2E-тест
   от сетевого файла до ответа Chat.
4. Подготовить наглядную демонстрацию.

==================================================
1. INSPECT FIRST
==================================================

Изучи текущие:

- MCP Network File Connector;
- Source SyncService;
- RunService / Pipeline / Ingestor;
- Docling integration;
- normalized document/page/block storage;
- chunking и indexing;
- Search / Chat / citations;
- Sources UI;
- существующие тесты Day31.

Сохранить существующую архитектуру.

==================================================
2. REAL NETWORK FOLDER
==================================================

В существующем табе /sources
должна работать настройка UNC-пути:

\\server\share\folder

Путь вводится пользователем.

Не создавать фиктивный сетевой адрес.

Проверить:

- доступность;
- read-only permissions;
- перечисление каталогов;
- чтение файлов;
- отсутствие выхода за разрешенный root;
- поддержку кириллицы в путях;
- обработку сетевых ошибок.

Использовать права текущего процесса.

Не записывать SMB credentials
в настройки приложения.

Если реальный путь пока не указан
или сетевой ресурс недоступен,
не заявлять об успешном SMB E2E.

==================================================
3. DOCX SUPPORT
==================================================

Исправить текущую ситуацию:

DOCX → UNSUPPORTED_FORMAT.

Реализовать DOCX как дополнительный
формат существующего ingestion.

Предпочтительно использовать
уже установленный Docling.

Не создавать отдельную систему
обработки Word-документов.

Обеспечить извлечение:

- текста;
- заголовков;
- абзацев;
- таблиц;
- списков;
- структурных блоков.

Сохранять порядок содержимого.

Результат приводить
к существующему canonical format.

Если для DOCX требуются изменения
canonical adapter,
сделать их совместимыми
с текущим PDF pipeline.

==================================================
4. SOURCE REFERENCES
==================================================

DOCX не имеет надежных фиксированных
номеров страниц.

Поэтому:

- сохранять document ID;
- section/heading;
- block ID;
- исходный текст;
- provenance.

Не выдавать логический блок
за реальную страницу DOCX.

Цитаты должны открывать
соответствующий документ
и доступный структурный фрагмент.

==================================================
5. TABLES
==================================================

Особое внимание таблицам.

Для страховых документов
это критически важно.

Проверить, что таблица вида:

Страховой случай | Исключение | Условие выплаты

не превращается в бессвязный текст.

Сохранять связь между строками
и столбцами настолько,
насколько поддерживает
существующий normalized format.

==================================================
6. EXISTING PIPELINE
==================================================

После нормализации DOCX
использовать тот же путь:

canonical content
→ existing chunker
→ BGE-M3
→ Qdrant
→ retrieval
→ reranker
→ ContextBuilder
→ GenerationProvider
→ grounding/citations.

Не создавать DOCX-specific RAG.

==================================================
7. NETWORK SYNC
==================================================

Проверить:

FIRST SCAN:
NEW → ingestion.

SECOND SCAN:
UNCHANGED → 0 повторных ingestion.

MODIFIED:
новая версия файла
→ корректная переобработка.

MISSING:
без автоматического удаления.

NETWORK ERROR:
не помечать массово файлы MISSING.

Не индексировать файл,
который еще копируется.

==================================================

одного проиндексированного документа.

страховыми согласно этому документу?
Укажи подтверждающие положения."

Но только если документ
действительно содержит такие сведения.

Не подменять настоящий источник
синтетическим при заявлении
о реальном E2E.
