ЗАДАЧА

Рефакторинг Web UI.

Сейчас в Chat одновременно находятся:

- выбор области поиска;
- дерево и список документов;
- статусы сетевых источников;
- сам диалог;
- память задачи.

Это создает перегруженный интерфейс
с несколькими вложенными прокрутками.

Разделить эти функции.

==================================================
1. INSPECT FIRST
==================================================

Изучи существующие:

- navigation/layout;
- Chat page;
- Sources page;
- document registry;
- source scope selector;
- RetrievalPolicy;
- ChatSession;
- document viewer;
- HTMX/SSE;
- CSS components.

Переиспользовать существующие
templates, API и services.

==================================================
2. NEW TAB
==================================================

Добавить вкладку:

"Каталог документов"

Использовать существующий
FastAPI + Jinja2 + HTMX.

Не добавлять frontend framework.

==================================================
3. CATALOG CONTENT
==================================================

В каталоге разместить:

Верхняя панель:

[Область ▼]
[Источник ▼]
[Поиск по имени]
[Формат ▼]
[Статус ▼]

Далее:

- дерево каталогов;
- таблица документов;
- пагинация;
- счетчики;
- статусы обработки.

В таблице:

Название
Источник
Путь
Формат
Размер
Дата изменения
Статус обнаружения
Ingestion
Indexing
Действия.

==================================================
4. DIRECTORY TREE
==================================================

Перенести дерево документов
из Chat в новый Catalog.

Поддержать:

- раскрытие каталогов;
- ленивую загрузку;
- поиск файлов;
- выбор папки;
- фильтрацию списка.

Не загружать всё дерево
огромного сетевого архива одним HTML.

==================================================
5. STATUS
==================================================

Отображать фактические статусы:

DISCOVERED
QUEUED
PROCESSING
INDEXED
FAILED

Также:

NEW
MODIFIED
UNCHANGED
MISSING

Не считать обнаруженный файл
готовым к RAG.

Данные брать из существующего
Source Registry / Ingestion.

==================================================
6. ACTIONS
==================================================

Для документа:

[Открыть]
[Обсудить в Chat]

"Открыть":
использовать existing document viewer.

"Обсудить в Chat":
создать новый ChatSession
или использовать существующий
механизм явного изменения scope.

Выбранный документ должен быть
реальным ограничением retrieval,
а не только подписью в UI.

Если индекс отсутствует,
не позволять выдавать документ
за доступный для RAG.

Не изменять scope других сессий.

==================================================
7. CLEAN CHAT
==================================================

Убрать из Chat:

- подробный список документов;
- дерево каталогов;
- поиск по именам файлов;
- счетчики сканирования;
- технические статусы MCP/ingestion.

Оставить:

Левая колонка:
история чатов.

Центр:
сообщения и ответы.

Справа:
сворачиваемая память задачи.

Сверху над диалогом:
компактный выбор области поиска.

Снизу:
поле сообщения и отправка.

==================================================
8. SOURCE SCOPE
==================================================

В Chat сохранить:

Все документы
Сетевые источники
Загруженные вручную
Конкретный источник.

Текущий выбор должен:

- сохраняться в ChatSession;
- применяться до retrieval;
- работать в Point RAG;
- работать в Exhaustive;
- сохраняться при follow-up.

Не допускать поиска
за пределами выбранного scope.

==================================================
9. CHAT UX
==================================================

Устранить лишние вложенные
прокрутки.

На desktop:

- история слева;
- диалог по центру;
- память справа, сворачиваемая.

Основной scroll —
для истории сообщений.

Поле ввода остается доступным
при длинном диалоге.

На небольших экранах
боковые панели можно скрывать.

Не менять бизнес-логику Chat.

==================================================
10. KEEP EXISTING SOURCES TAB
==================================================

Таб "Источники документов"
остается для:

- добавления SMB/NAS;
- управления источниками;
- настройки расписания;
- запуска сканирования;
- ошибок подключения;
- истории синхронизации.

Не дублировать его
административные функции
в новом Catalog.

==================================================
11. KEEP EXISTING SEARCH
==================================================

Таб "Поиск" не менять.

Он продолжает выполнять
существующие RAG experiments.

Новый "Каталог документов" —
поиск и просмотр файлов,
а не второй semantic retrieval.

==================================================
12. /help
==================================================

Существующий /help
должен продолжить работать.

Для ответов по документам:
existing RAG.

Для вопросов о состоянии архива:
existing Source/Sync Registry.

Не создавать второй Document Assistant.

==================================================
13. UI STATE
==================================================

Сохранять:

- выбранный источник;
- фильтры каталога;
- текущую страницу;
- раскрытые папки,
  если существующий UI позволяет.

При переходах между табами
не сбрасывать без необходимости
ChatSession и source scope.

==================================================

==================================================

Проверить:

A. Новый Catalog открывается.

B. Дерево каталогов отображается.

C. Фильтр источника работает.

D. Поиск по имени файла работает.

E. Статусы соответствуют SQLite.

F. Document viewer открывается.

G. "Обсудить в Chat"
   передает правильный document scope.

H. Chat больше не содержит
   таблицу и дерево документов.

I. ChatSession сохраняет source scope.

J. Point RAG и Exhaustive
   соблюдают ограничения.

K. /help работает.

L. Sources и Search не сломаны.

M. История чатов и память
   работают как раньше.

Запустить полный test suite.

==================================================
15. ACCEPTANCE
==================================================

Итоговый интерфейс:

ИСТОЧНИКИ
→ подключаем сетевой каталог.

КАТАЛОГ
→ видим обнаруженные документы,
   статусы и содержимое.

ЧАТ
→ выбираем область поиска,
   задаем вопросы,
   получаем ответы с цитатами.

ПОИСК
→ существующие RAG experiments.

Никакого дублирования
логики или интерфейсных элементов.
