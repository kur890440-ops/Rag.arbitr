# Day 25 · Policy revalidation / Predicate evaluation / Rewrite guard

1. **Primary root cause.** `ReferenceAwareRetrievalService.verify()` одним structured verdict просил одновременно подтвердить prior claim и связь с текущим вопросом. Для «не относится к отчётности» модель возвращала пустые refs; последующая проверка GroundingValidator неизбежно получала `grounded=false`, и это сохранялось как `supported_under_current_policy=false / NOT_RECONFIRMED`. Отрицательная принадлежность теме ошибочно становилась отсутствием доказательства исходного факта.
2. **Смешивавшие функции.** `ReferenceAwareRetrievalService.queries()` добавлял predicate в каждый claim query; `verify()` смешивал два вопроса, а построение AnswerContract превращало отсутствие positive claims в общий insufficient_context. Эти старые пути удалены. Binding прежних qualified IDs сохранён.
3. **Модули.** Добавлен `application/policy_predicate.py`: `PriorClaimPolicyRevalidator`, `PredicateEvaluator`, `ReferenceAnswerBuilder`, schemas и orchestration `execute_reference`. Изменены `reference_retrieval.py`, `rag.py`, `query_rewrite.py`, trace-copy в `chat.py`, observer allowlist в `dialogue.py`, `chat_diagnostic.py`, тесты/fixtures, live script и README. TaskState, RetrievalPolicy, WorkingContext, ReferenceResolver, router semantics, taxonomy, OCR/chunking, BGE, Qdrant collections, модели и пороги reranker/grounding не менялись.
4. **ClaimPolicyValidationResult.** `claim_id`, `claim_text`, `status=REVALIDATED_EXISTING_SOURCE|REVALIDATED_NEW_SOURCE|NOT_RECONFIRMED|UNKNOWN`, `supporting_source_ids`, `policy_version`, `reason`; дополнительные `old_source_checks`, `source_reused`, `fresh_retrieval`, `fresh_query`, `comparison_run_id`.
5. **PredicateEvaluationResult.** `claim_id`, `claim_text`, `predicate`, `status=MATCH|NO_MATCH|UNKNOWN`, `supporting_source_ids`, `reason`, `confidence`. Модель возвращает только ID/status/refs/reason/confidence; canonical text и predicate добавляет приложение из проверенных входов. Mapping должен содержать все и только revalidated IDs ровно один раз. UNKNOWN не преобразуется в NO_MATCH.
6. **Reuse evidence.** Canonical prior comparison должен содержать тот же SUPPORTED claim, source turn — GROUNDED. Для каждого original supporting source проверяется current policy; точная сохранённая citation должна совпадать с canonical block/locator, относиться к тому же документу и active chunk, иметь достаточный исходный support score. Выбирается одно допустимое доказательство с наибольшим score. В Stage B передаётся точная цитата, а не весь старый контекст. Сохраняются old source ID/turn, reused citation и policy checks. Это не автоматическое признание любого текста prior answer доказательством.
7. **Fresh retrieval.** Только если пригодного old evidence нет: источник запрещён, canonical data недоступны/изменены, chunk не активен либо claim не подтверждён. Используется существующий `RAGComparisonService` в RERANK mode с текущей policy; специальная revalidation ветка проверяет исходный claim через существующий GroundingValidator вместо новой генерации ответа. Создаётся связанный comparison для аудита. При отсутствии подтверждения — NOT_RECONFIRMED, при ошибке выполнения — UNKNOWN; оба исключаются из Stage B.
8. **Fresh query.** Ровно canonical `prior['claim_text']`, например «Конкурсный управляющий обязан принимать меры, направленные на поиск, выявление и возврат имущества должника.» Без Query Rewrite, broad goal и новых qualifiers. Не более `max_reference_claims` поисков (default 10), один на claim без пригодного old evidence; при полном reuse — 0. Query embeddings этой fallback ветки последовательные через существующий engine, не новый batch pipeline.
9. **Predicate отсутствует в Stage A.** Query проверяется на равенство claim_text. Если слово об отчётности уже содержится в самом prior claim, оно законно остаётся; текущий follow-up не конкатенируется. Тест реального fallback при исключении жалобы проверяет именно этот контракт.
10. **MATCH.** Отдельная модель определяет подтверждённую связь с predicate по admissible evidence и сохраняет confidence/refs. Неизвестные или чужие refs и низкая confidence превращаются в UNKNOWN. Только canonical тексты MATCH claims проходят обычный Day24 GroundingValidator и получают positive citations; выдуманный свободный ответ модели не публикуется.
11. **NO_MATCH.** Уверенная семантическая непринадлежность данного revalidated утверждения текущему условию. Prompt запрещает выводить её лишь из отсутствия слова в короткой цитате и запрещает внешние юридические знания. Сохраняются supporting refs, reason/confidence и Stage A provenance. Это probabilistic semantic evaluation, не математическое доказательство отсутствия обязанности во всём корпусе.
12. **UNKNOWN.** Недостаточная evidence, низкая confidence, неверные refs либо positive MATCH, не прошедший Day24. Если все результаты неизвестны/не revalidated — INSUFFICIENT_CONTEXT. При смешанном результате известные MATCH/NO_MATCH сохраняются, неизвестные и NOT_RECONFIRMED явно перечисляются.
13. **All NO_MATCH.** Только когда все исходные claims revalidated и все получили NO_MATCH: `VALID_EMPTY_RESULT` и ответ «Из ранее перечисленных и повторно подтверждённых утверждений ни одно напрямую не соответствует текущему условию». Фиктивные positive claims/citations не создаются. Наличие хотя бы одного UNKNOWN/NOT_RECONFIRMED исключает такой полный отрицательный вывод. Когда есть только MATCH+NO_MATCH, ответ содержит MATCH; при частичной неизвестности дополнительно сообщает известное отрицательное и неизвестное.

18. **Root cause guard.** Разность множеств буквальных `\w+` токенов считала «связанные» новым фактом, хотя это обычная словоформа «связаны». Guard ошибочно проверял лексическое совпадение вместо новых protected qualifiers.
19. **Morphology.** Обычные слова больше не сравниваются на буквальное включение. Поэтому склонение, спряжение, перестановка, удаление filler и новые обычные синонимы не требуют морфологической ML-модели. Для распознаваемых qualifiers нормализуются регистр, пробелы, ё/е, дефисы; статьи и document types выделяются по устойчивым основам/типам.
20. **Protected qualifiers.** Лёгкие typed recognizers: LEGAL_ARTICLE, DATE, MONEY, CASE_NUMBER, PERSON_NAME, ORGANIZATION_NAME, DOCUMENT_TYPE, DOCUMENT_ID, EXPLICIT_IDENTIFIER. Новые распознанные qualifiers сравниваются только с current question/predicate, referent label, canonical prior claims и explicit semantic conditions/terms. Arbitrary corpus text не разрешает новый qualifier. При drift остаются GUARDED_FALLBACK / SEMANTIC_DRIFT_REJECTED. В trace — original/proposed, normalized comparison, allowed/original/proposed/new qualifiers, решение и причина. Regex recognizers не являются универсальным NER и могут ошибаться на редких формах; они не доказывают полную семантическую эквивалентность произвольного перефразирования.
21. **Safe example.** `test_safe_morphology_and_paraphrase`: «Какие обязанности связаны с отчетностью?» → «обязанности, связанные с отчетностью»; также управляющий/управляющего, обязанность/обязанности, продлить/продление, срок/сроки и обычный paraphrase.
22. **Injected article.** `test_new_factual_qualifier_rejected_allowed_preserved`: добавленное «по статье 129» отсутствует в allowed inputs → fallback к исходному. При явном присутствии в разрешённых входах тот же qualifier принимается. Аналогичные проверки для даты, денег, номера дела, лица, организации, вида/ID документа и ИНН.
