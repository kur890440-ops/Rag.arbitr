# Day 24 — Grounding & Citations

Дата: 2026-10-03. Реализация усиливает существующий Point RAG после Day23 retrieval.
Новая вкладка, отдельный pipeline, LLM judge, agent, hybrid search, BM25 и routing не добавлены.

## Реализация и проверка — 30 пунктов

1. **Переиспользованные компоненты.** SemanticRetriever, CandidateProcessor, ContextSelector, RAGContextBuilder, QueryRewriteService, LocalReranker, MiniMaxLLMProvider, SQLite MetadataStore, RAGComparisonService и Recognition Viewer. NO CONTEXT и EXHAUSTIVE NO RAG сохраняют прежние контракты.

2. **Generation output.** Для Point RAG добавлен `LLMRequest.context_type=grounded_rag`: JSON `answer`, `claims`, `insufficient_context`, `clarification_request`. Исходный вопрос не заменяется retrieval query. Модель выбирает только предоставленные S1…Sn; приложение добавляет ссылки к проверенным утверждениям. Некорректный JSON не показывается пользователю как ответ.

3. **Claim model.** `GroundedClaim`: claim_id, text, supporting_source_ids, support_status, support_scores, repair_status. Повторяющиеся claim_id и факты в answer, отсутствующие в claims, не проходят проверку. Покрытие проверяется консервативно: answer должен совпадать с соединёнными текстами claims с нормализацией пробелов. Это может отклонять корректное переформулирование.

4. **CitationBuilder.** Выбирает короткие предложения/абзацы/блоки из канонического текста. Проверяет принадлежность блока документу и pinned anchor/expanded chunks, а также присутствие фрагмента в реально переданном контексте. На один источник рассматривается максимум шесть кандидатов; среди прошедших проверку выбирается короткий. Это ограничение может приводить к отказам.

5. **Canonical text.** SQLite `document_blocks` по source_block_ids и pinned `chunks`. Числа, ФИО и цитаты из ответа MiniMax не используются как канонический источник. Нет fallback с выдуманным locator. В citations сохраняются только короткая цитата, идентификаторы и locator; большие контексты повторно не копируются.

6. **Exactness.** `CitationBuilder.exact()` повторно читает блок, проверяет document_id, recognition_id, page_number и точное равенство `text[start:end] == quote`. Парафраз не считается точной цитатой. Навигация ведёт на страницу канонического блока, которая может отличаться от anchor page расширенного контекста.

7. **GroundingValidator.** Проверяет каждый заявленный source ID, строит цитаты, оценивает пары claim/quote и применяет дополнительные запреты на отсутствующие числа, имена, отрицание и существенные слова. Все фактические утверждения должны пройти проверку. При одной плохой части весь ответ безопасно отклоняется, если единственное исправление не помогло.

8. **Day23 reranker.** Используется тот же долгоживущий LocalReranker с BAAI/bge-reranker-v2-m3, без отдельной inference stack. Важно: cross-encoder оценивает релевантность, а не логическое следование. В реальном тесте обнаружен ложный высокий балл для одной даты вместо подтверждения ФИО; после этого усилены лексические проверки и сохранённые ответы перепроверены локально.

9. **Порог поддержки.** По умолчанию `0.5` для sigmoid claim_support_score. Это начальный инженерный порог, не откалиброванная вероятность истинности.

10. **Настройка.** `[llm] claim_support_threshold` в локальном config.toml; поле API `claim_support_threshold`; Search → Advanced → Claim support threshold. Диапазон 0…1, NaN/Infinity запрещены. Snapshot фиксирует порог конкретного сравнения. Ключ API не попадает в snapshots, отчёты или Git.

11. **Три оценки.** Retrieval score остаётся исходной метрикой векторного поиска. Rerank score определяет порядок/отсев найденных кандидатов. Support score вычисляется заново для пары утверждение/цитата и хранится в Citation и GroundedClaim. Эти шкалы не складываются и не сравниваются напрямую.

12. **Relevance gate.** Использует существующий отбор Day23: minimum_candidate_score и rerank_threshold. Если финальные contexts пусты, возвращает `INSUFFICIENT_CONTEXT`. BASELINE сохраняет свою политику, а его непустые контексты дополнительно проверяются после generation.

13. **Zero contexts.** Ноль вызовов factual generation; текст: «Не знаю по имеющимся документам. Релевантных источников недостаточно. Уточните вопрос». Ошибки индекса/провайдера остаются техническими ошибками, а не маскируются под отсутствие ответа. Ответ NO CONTEXT никогда не используется как подмена.

14. **Repair input.** Исходный вопрос, текущий ответ, claims со статусами и причинами, прежние source contexts. Ни нового retrieval, ни новых source IDs. Нарушение JSON/coverage также может получить одну коррекцию. Ожидания контрольных вопросов не отправляются модели.

15. **Максимум один repair.** Основной код использует цикл с двумя итерациями: исходная генерация и один repair. Для сохранённой дополнительной пробы использован только её ещё не израсходованный repair. Вторая коррекция одного ответа запрещена. Всего в разрешённых 12 проверках выполнено 10 HTTP-запросов generation/repair; полный просмотр не запускался.

16. **Revalidation.** После repair повторяются JSON, refs, coverage, canonical extraction, exactness, support. Неуспех заканчивается отказом без вывода непроверенного factual answer. При усилении валидатора ранее полученные результаты перепроверены локально без новых исходных генераций; историческая диагностика сохранена.

17. **RAG panel.** Сохранились три панели. В «С RAG» добавлены статус grounding, число утверждений/подтверждений/цитат/источников, repair и раскрываемая диагностика. Старые сравнения без Day24 не получают задним числом признак grounded.

18. **Sources.** Прежний список переданных контекстов сохраняет S1…Sn, файл, страницу, раздел, chunk, retrieval/rerank scores и полный context text. Детали показывают поддержку каждого claim. Число источников в grounding summary относится к подтверждающим цитатам, а не ко всем найденным контекстам.

19. **Citations.** Отдельные HTML blockquotes с точным normalized text, claim/source IDs, файлом, разделом, chunk, страницей, exact_match и support_score. Кнопка страницы использует прежний Recognition Viewer. HTML источников экранируется шаблонизатором.

20. **Answerable test.** Существующий вопрос о сроке продления конкурсного производства ООО «РУСМЕТ» получил ответ «на 6 месяцев». Цитата из ходатайства: `продлить срок конкурсного производства в отношении ООО "РУСМЕТ" на 6 месяцев.` Одна страница, один source, один claim, одна exact citation; repair не потребовался. Comparison `d919e7ccd71a4f1891e19499c261fb89`.

21. **Multi-claim test.** Дополнительный вопрос о заявителе и сроке продления дал два claims. После усиленной проверки и единственного repair одна часть не подтвердилась; итог — INSUFFICIENT_CONTEXT, неподтверждённый ответ не показан. Это провал полезности ответа на известный вопрос, а не успешный multi-fact ответ. Comparison `a461a0257ffc48baa87bc4329791a2f6`.

22. **Unanswerable test.** Вопрос о периоде обращения Ганимеда вокруг Юпитера. До теста просмотрен полный набор 866 активных normalized blocks всех 16 документов; отсутствуют Юпитер, Ганимед, Каллисто и соответствующие астрономические упоминания. Проверка относится именно к распознанному корпусу, не ко всем исходным PDF. Результат NO_RELEVANT_CONTEXT → INSUFFICIENT_CONTEXT, без factual generation. Comparison `b9c7bf6f471f4fe3ae691cbbea2ce9c8`.

23. **Evaluation.** Все 10 существующих вопросов сохранены без замены; отдельно выполнены две acceptance-пробы. Unanswerable явно помечен в сохранённом comparison через expected_unanswerable; UI редактирования контрольных вопросов также поддерживает эту отметку. Большинство старых вопросов требуют обзора всего корпуса; Point RAG не гарантирует полноту такого обзора. Результаты и идентификаторы: `data/day24/01.json`…`12.json`; сводка `data/day24/evaluation.json`; аудит отсутствия `data/day24/absence-audit.json`. Эти файлы исключены из Git.

24. **Sources coverage.** Итоговые числа после перепроверки приведены в таблице ниже. Отказ не считается factual answer с источниками, даже если retrieval нашёл контексты.

25. **Citation coverage.** Считаются только цитаты фактически показанных grounded answers. Точные цитаты не доказывают полноту или истинность всего ответа сами по себе.

26. **Supported claims.** В метриках учитываются также проверенные части отклонённых ответов; это диагностическая сумма, а не число показанных утверждений. Отдельно в таблице указано число фактических ответов, прошедших все проверки.

27. **Unsupported claims.** Неподтверждённые части остаются в диагностике и не выводятся как grounded factual answer. Лексическая проверка намеренно консервативна и может отклонять правильные парафразы или факты, требующие соединения разных блоков.

28. **Correct refusals.** Только один вопрос имеет проверенную метку отсутствия ответа. Его отказ считается correct refusal. Другие отказы нельзя объявлять правильными автоматически: среди них есть вопросы с известным ответом.

29. **Tests.** Результат окончательного прогона и проверки браузера приведён ниже. Покрыты неизвестные ссылки, точность цитат, provenance, разделение scores, несколько sources, coverage, отказ до generation, слабый контекст, один repair, повторная валидация, source navigation и Day21–23 regressions. Синтетические LLM fixtures обновлены под structured contract, а не отключают grounding.

30. **Blockers и ограничения.** Разрешение на внешние Day24-тесты получено явно; первоначальная блокировка auto-review устранена. Техническая реализация и сохранение результатов выполнены. Качество полезных ответов пока низкое: строгая проверка часто отказывает, multi-claim acceptance не дал полного ответа. Semantics остаётся эвристикой и не является гарантией отсутствия галлюцинаций. Порог не обучен на размеченном наборе, в UI нет скрытого «победителя». Следующий день курса не реализован.

## Уточнение repair для суммы убытков БРК

В сравнении `00cfc31a0983445382bfac3d61952a25` источник S1 содержал сумму на странице 7, но сгенерированное утверждение также называло банк, отсутствующий в этой цитате. Обе попытки повторяли утверждение. Дополнительно диагностическая причина перезаписывалась последним проверенным фрагментом и не соответствовала показанному максимальному score.

В `day24-2` score и причина относятся к одной цитате; `quote_checks` содержит фрагменты, локаторы, причины и неподтвержденные слова. Инструкция требует краткого ответа на запрошенный факт, а единственный repair получает конкретные основания отклонения. Пороги и правила принятия утверждений не ослаблены.

Проверка: 47 тестов grounding/RAG прошли. Локальный replay сохранённых источников с настоящим reranker подтвердил «Размер убытков — 4 104 326 405,76 рублей», точная цитата на странице 7, score 0.9910. Это проверка валидатора, а не новая генерация MiniMax. Исторический результат не изменён; поведение нового LLM-ответа проверяется новым сравнением в UI.
