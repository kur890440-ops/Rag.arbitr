ЗАДАЧА

Доработать существующий Chat:

- выбор источников документов;
- отображение результатов сканирования;
- автоматическое обновление списка файлов;
- поиск исключительно по выбранному источнику;
- демонстрация полного MCP → RAG workflow.

==================================================
1. INSPECT FIRST
==================================================

Исследуй существующие:

- Chat UI и ChatSession;
- RetrievalPolicy;
- Point RAG;
- Exhaustive mode;
- Source registry;
- MCP connector;
- Source SyncService;
- ingestion status;
- canonical document storage;
- Qdrant metadata;
- source navigation;
- текущий READ_ERROR.

Не создавать параллельные компоненты.

==================================================
2. SOURCE SELECTOR
==================================================

В существующем Chat добавить:

Область поиска:
[Все документы ▼]

Варианты:

Все документы
Сетевые источники
Загруженные вручную

При выборе сетевых источников:

Источник:
[Доки ▼]

Источники получать из SQLite.
Не hardcode названия.

Сохранять выбор в ChatSession.

При новом выборе
применять обновленный scope
ко всем следующим запросам.

==================================================
3. DOCUMENT DISCOVERY PANEL
==================================================

Под выбором источника добавить
компактную раскрываемую панель:

"Найденные документы"

В заголовке:

Источник: Доки
Последний scan: дата/время
Следующий scan: дата/время
Статус: SUCCESS / ERROR

Счетчики:

Всего обнаружено
Новых
Измененных
Проиндексировано
В обработке
Ошибок

Ниже таблица:

Имя файла
Формат
Обнаружен
Статус обработки
Статус индексации
Действие

Пример:

Договор.docx | DOCX | NEW | COMPLETED | INDEXED | Открыть

Это только пример.
Все значения брать из реальной БД.

==================================================
4. AUTO REFRESH
==================================================

Обновлять панель при изменении
состояния сканирования/ingestion.

Использовать существующие
HTMX/SSE или polling.

Не добавлять новый frontend framework.

Не создавать отдельный scheduler.

Автоматический scan использовать
из существующих настроек источника.

Показывать состояние автосканирования
и планируемое время следующей проверки,
только если расписание реально работает.

==================================================
5. SCAN BUTTON
==================================================

В панели добавить:

[Сканировать сейчас]

Кнопка вызывает существующий
Source SyncService.

Не реализовывать второй сканер.

Если сканирование уже выполняется,
не запускать конкурентный scan
того же источника.

==================================================
6. SOURCE FILTERING
==================================================

КРИТИЧЕСКИ:

source_id должен ограничивать
набор допустимых документов
ДО retrieval.

Не фильтровать результаты
только после генерации.

Не ограничиваться инструкцией LLM
"отвечай только по источнику".

Использовать существующий
RetrievalPolicy и canonical provenance.

Для Qdrant обеспечить
корректную фильтрацию по source_id
или по разрешенным документам/chunks.

Если необходимых metadata нет,
добавить безопасный способ фильтрации
без второго индекса.

Не допускать незаметного
fallback к поиску по всему корпусу.

==================================================
7. CHAT MODES
==================================================

Проверить source scope для:

- Point RAG;
- Exhaustive;
- follow-up сообщений;
- сохраненных ChatSession.

Для follow-up сохранять
выбранную область поиска,
если пользователь ее не изменил.

Существующие другие фильтры
RetrievalPolicy сохраняются.

Новый source scope
не должен их отменять.

==================================================
8. INDEXED DOCUMENTS
==================================================

Показывать отдельно:

DISCOVERED — файл найден;
PROCESSING — обрабатывается;
INDEXED — индекс готов;
FAILED — ошибка.

Только INDEXED и другие
подтвержденно доступные
в активном retrieval/index
документы участвуют в поиске.

Если новых документов еще нет
в индексе, сообщать это явно.

==================================================
9. SOURCE NAVIGATION
==================================================

Для каждого файла с canonical document ID
добавить:

[Открыть документ]

Использовать существующий
document viewer/registry.

Для цитат DOCX использовать
реальные section/block references.

Не придумывать номера страниц.

==================================================
10. READ_ERROR
==================================================

На текущей форме сетевой источник
отображает дерево папок,
но полный scan завершился:

READ_ERROR.

Сначала установить точную причину.

Проверить:

- SMB access;
- traversal;
- чтение файлов;
- permissions;
- обработку служебных файлов;
- ошибки MCP protocol;
- файловую стабильность.

Исправить подтвержденную причину
без ослабления root security.

Не маскировать ошибку.

Панель Chat должна отображать
реальный статус ERROR
и понятную причину.

==================================================
11. AUTOMATIC SCAN
==================================================

Проверить существующее расписание.

Если автосканирование предусмотрено,
но фактически не запускается,
исправить wiring/scheduler.

При включенном auto scan:

новый файл появляется
в source registry
после очередного сканирования.

Не запускать scan
при каждом Chat request.

==================================================
12. REAL E2E
==================================================

На разрешенной сетевой папке:

1. Проверить доступ.
2. Выполнить scan.
3. Получить список найденных файлов.
4. Убедиться, что UI Chat
   показывает эти же файлы.
5. Добавить тестовый PDF/DOCX
   только в разрешенную тестовую папку.
6. Дождаться automatic scan
   либо запустить ручной.
7. Проверить статус NEW.
8. Дождаться ingestion/indexing.
9. Проверить INDEXED.
10. Выбрать нужный источник в Chat.
11. Задать вопрос по документу.
12. Получить ответ с цитатой.
13. Повторить scan.
14. Подтвердить UNCHANGED
    и отсутствие повторного ingestion.

Если реальный NAS недоступен,
не заявлять успешный SMB E2E.

==================================================
13. ISOLATION TEST
==================================================

Создать два тестовых источника:

SOURCE A
SOURCE B.

В каждом разные документы.

При выборе SOURCE A:

Chat должен использовать
только документы A.

Документы B не должны
попадать в retrieval/context/answer.

Проверить обратное направление.

Проверить режим "Все документы".

==================================================
14. REGRESSION TESTS
==================================================

Проверить:

- source selection;
- session persistence;
- follow-up scope;
- Point RAG filtering;
- Exhaustive filtering;
- scan status отображается;
- ERROR не превращается в пустой список;
- новые документы появляются в панели;
- INDEXED соответствует реальному индексу;
- source navigation;
- Search/Chat regressions;
- отсутствие повторного ingestion.

Запустить полный test suite.
