# Day33 — публичный консультант по страхованию

Реализовано и проверено локально; результаты и границы проверки приведены ниже. Задание сохранено без сокращения в `DAY33_PUBLIC_CONSULTANT_TASK.txt`.

## Архитектура и границы

Публичный `/consult` — адаптер существующего приложения FastAPI/Jinja2/HTMX, не отдельный Agent или индекс. Используются `ChatSession`, `DialogueWorkingContext`, `WorkingContextService`, `ReferenceResolver`, расширенный `AnswerModeRouter`, `RetrievalPolicyBuilder`, `RAGComparisonService`, `RAGContextBuilder`, `ExhaustiveNoRAG`, существующий grounding с максимум одним repair и `MiniMaxLLMProvider`.

`ConsultService` управляет только временным посетителем, лимитами и вызовами этих компонентов. На запрос создаётся поверхностная копия существующего сервиса RAG для привязки ограниченного MiniMax factory; хранилище, индексы и reranker остаются общими. Внутренние настройки моделей не меняются. Генеративные вызовы публичной цепочки используют MiniMax; BGE/reranker остаются локальными негенеративными моделями.

## Публикация

Внутренний интерфейс `/publications`, ссылка «Публикация» в Chat. По умолчанию PRIVATE. Администратор локального приложения явно включает PUBLIC для пары `canonical_document_id + recognition_version`. Разрешение хранится в существующей SQLite metadata model, таблица `public_document_grants`. Нет публикации источника целиком или наследования разрешения новой версией.

Проверяется готовность canonical storage и committed index. Из допустимых версий собирается snapshot существующих partition; `RetrievalPolicy` передаётся в существующий поиск Qdrant до `candidate_top_n`. Пустой public scope никогда не заменяется приватным. Для сетевых документов также проверяется действующее разрешение источника.

Перед каждым вызовом MiniMax и выдачей ответа сверяется ревизия публикации. Отзыв запрещает новые ответы/переходы и очищает связанный контекст посетителя при следующем обращении. Уже показанный в браузере текст невозможно отозвать задним числом.

## Режимы и диалог

`GENERAL`, `DOCUMENT`, `MIXED` — typed semantic routing MiniMax, не набор ключевых слов. Router видит текущий вопрос, ограниченную историю, рабочий контекст и только публичные названия. Конкретный отсутствующий документ не подменяется доступным.

GENERAL отвечает без RAG. DOCUMENT использует Point RAG или Exhaustive для полного охвата/сравнений. MIXED разделяет общий вопрос и вопрос о договорных условиях, отображает общие сведения отдельно от подтверждённого ответа. История помогает разрешить тему, но не заменяет свежие доказательства.

Point использует существующий claim/citation validation и repair. Exhaustive использует существующую проверку точных evidence spans; публичное представление показывает проверенные извлечения вместо непроверенного свободного synthesis. Это консервативное ограничение качества: сравнение может выглядеть как набор цитируемых положений, а не плавное аналитическое резюме.

Versioned prompt: `day33-public-v1`, router: `DAY33_PUBLIC_ROUTER_V1`. Общие знания MiniMax не проходят документальную верификацию; их смысловая корректность оценивается отдельно от валидности JSON.

## Сессии и ограничения

Случайный непрозрачный cookie, HttpOnly, SameSite=Strict, Secure на HTTPS и принудительно на выделенном public listener; IP не является идентификатором диалога. Анонимные объекты ChatSession и контекст находятся только в памяти адаптера, отдельно от внутренних chat_sessions. TTL 3600 секунд, cleanup каждые 30 секунд и при обращении, максимум 200 посетителей. После перезапуска история исчезает. Временные публичные RAG/cache-записи удаляются после запроса; после аварии cleanup удаляет помеченные публичные записи по TTL (с запасом на текущий timeout). Внутренние RAG-записи не удаляются. Поддерживается один worker на публичный listener.

По умолчанию: 6 запросов/мин на session/IP, 30 общих запросов/мин, 2 параллельных ответа, 1500 символов ввода, 16 сообщений истории, 6000 байт консервативного бюджета истории, 24000 входного бюджета, 4096 output tokens, 120 секунд на цепочку, максимум 10 LLM calls. Лимит streamed body публичного POST — 20000 байт. Лимиты вызовов не растут автоматически; map retries отключены в публичной конфигурации.

Дневной лимит 1000000 единиц консервативной резервации input+output в SQLite `consult_usage`, общий между процессами. Для input используется UTF-8 byte upper bound, а не заявление о точной токенизации MiniMax. Резерв не возвращается при ошибке: это ограничение сверху, не счёт в валюте и не точная статистика расходов. IP/session throttling можно обходить сменой идентичности; общий лимит и резерв бюджета остаются.

Источники — `/consult/sources/{opaque_token}`, привязаны к посетителю и проверяемому разрешению; показаны только название, section/page и цитата. Никаких UNC paths или внутренних viewer URLs в публичном DTO. Markdown: HTML/images/links/autolinks модели отключены; ссылки на источники строит сервер.

## Разделение публичного и внутреннего доступа

Внутренние маршруты допускают только локальный peer (существующая модель локального административного приложения). Это НЕ система аккаунтов/ролей; администратор — доверенный пользователь локального приложения. Для внешнего reverse proxy обязательно отдельное приложение:

```powershell
.venv\Scripts\python.exe -m uvicorn rag_arbiter.web.consult:create_public_app --factory --host 0.0.0.0 --port 8766 --no-proxy-headers
```

Фабрика принудительно включает `consult.public_only`, запрещает все внутренние маршруты независимо от peer и отключает source scheduler этого listener. Нельзя публиковать внутренний listener через loopback proxy: такой proxy сам является локальным peer. Домен задаётся в существующем `web_allowed_hosts`; HTTPS и внешний reverse proxy здесь не развёрнуты. Основной локальный URL — `http://127.0.0.1:8765/consult`.

## Проверки

Реальные внутренние документы не публиковались и не передавались MiniMax. Пользователь явно разрешил синтетический страховой документ. Live-тест использует отдельную базу и реальные Docling, BGE, MiniMax и Edge; это не mock.

Подробные ответы и замеры: `data/day33-e2e/evidence.json`, `evidence-first-live.json`, `evidence-extended.json`. Артефакты исключены из git. Первая попытка без сетевой эскалации вернула NETWORK_ERROR; это не live success. Первый доступный live-прогон выявил лишнюю франшизу в ответе об отказе и отказ grounding в MIXED; после правки router/prompt эти два сценария дали подтверждённые ответы. Ошибки не скрываются в истории проверок.

Новые тесты: `tests/test_public_consultant.py`. Они используют подставной MiniMax и настоящий существующий test pipeline/SQLite/Qdrant. Проверяют диалоги, empty scope, PRIVATE, цитаты и их отзыв, изоляцию, TTL, лимиты, concurrency, oversized input, XSS, неподтверждённый claim, Exhaustive и очистку cache. Эти результаты не заменяют live-проверку модели.

Первый полный прогон: 535 passed, 1 failed, 1 skipped (1302.20 с). Сначала тест каталога завершался по 40-секундному scan timeout; повтор с достаточным ожиданием показал устаревшую подготовку missing-index сценария: Day32 сохраняет закреплённый индекс версии отдельно от текущего network head. В тесте теперь явно недоступен и этот индекс; production versioning не менялся.

**Повторный полный прогон: 543 passed, 1 skipped, 0 failed (1073.72 с).** Пропущен opt-in `tests/test_integration.py`: нужен `RAG_INTEGRATION=1` для загрузки реальных моделей. Вместо выдачи skip за проверку выполнен отдельный описанный live Docling/BGE/MiniMax/Edge E2E.

Финальные проверки после последующих локальных правок лимитов/TTL/HTTPS: `tests/test_public_consultant.py` — **13 passed** (91.64 с); публичный сервис + существующий `tests/test_web.py` — **65 passed** (223.82 с); последние guard/isolation проверки — **2 passed** (14.98 с). Наборы пересекаются, результаты не суммируются. Предупреждения — deprecation Starlette TestClient/httpx и per-request cookies в тесте.

`git diff --check` — без ошибок. Последний сервер перезапущен после ожидания завершения задач; `GET /consult` = 200. Все исходные enabled-флаги источников восстановлены и проверены. Основная база имеет ноль PUBLIC-разрешений; администратор должен выбрать реальные разрешённые версии сам.

## Ограничения эксплуатации

- Публичный интернет-домен, TLS, reverse proxy не развёрнуты. Готов локальный `/consult` и закрытый для внутренних маршрутов public app factory. Не экспонировать обычный внутренний listener через reverse proxy.
- Публикация — доверенная локальная административная операция, без новой системы учётных записей. Никакие реальные внутренние документы автоматически не публиковались.
- Один worker на public listener; временные сессии не переживают рестарт и не распределяются между workers. Дневной бюджет SQLite общий, минутные лимиты/конкурентность — на процесс.
- GENERAL — сведения модели, не юридическая экспертиза; точные цитаты не являются доказательством безошибочной смысловой интерпретации.
- Exhaustive не выдаёт непроверенный свободный synthesis: отображает подтверждённые выдержки. При больших документах срабатывают лимиты, частичное покрытие не объявляется полным.
- Синтетические privacy/injection tests и 16 live/UI вопросов не доказывают устойчивость к любым атакам. Цель hard scope подтверждается отдельно проверкой policy до candidate limit.
