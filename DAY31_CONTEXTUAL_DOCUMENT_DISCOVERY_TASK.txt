ЗАДАЧА

Переделать уведомления Day31.

Сейчас работает автоматическое
MCP-сканирование и toast об индексации.

Нужно учитывать активную область Chat.

==================================================
1. INSPECT FIRST
==================================================

Изучи:

- существующие notifications/events;
- Source SyncService;
- Source Registry;
- Document Registry;
- indexing readiness;
- ChatSession scope;
- selected_document_ids;
- RetrievalPolicy;
- Chat header;
- existing HTMX/SSE/polling.

Переиспользовать реализованные механизмы.

==================================================
2. TARGET BEHAVIOR
==================================================

Если:

- текущий Chat использует источник S;
- область ограничена конкретным
  выбранным набором документов;
- при автоматическом сканировании S
  обнаружены новые файлы;

то автоматически показывать
под областью анализа:

"В источнике S найдены новые документы."

Ниже:

- имена новых файлов;
- текущий статус каждого;
- количество готовых к анализу.

Не показывать modal/popover/toast
для тех же событий.

==================================================
3. INDEXING READINESS
==================================================

Различать:

NEW
PROCESSING
INDEXED
FAILED.

Сведения появляются при обнаружении,
а статусы обновляются автоматически.

Добавить в Chat можно
только документы с подтвержденной
готовностью активного индекса.

Не менять состав выбора
самостоятельно.

==================================================
4. USER CONFIRMATION
==================================================

Предложить:

[Добавить N документов]
[Не сейчас]

N = число новых,
готовых к анализу документов.

Если N = 0:
предложение добавления недоступно,
но состояние обработки показывается.

После подтверждения:

- дополнить текущий document selection;
- исключить дубликаты;
- сохранить изменения в ChatSession;
- обновить счетчик выбранных документов;
- использовать обновленный scope
  при следующих RAG-запросах.

Не изменять другие ChatSession.

==================================================
5. FILTERING
==================================================

Новый список документов
должен стать реальным ограничением:

RetrievalPolicy
→ Point RAG
→ Exhaustive.

Сохранять остальные ограничения
Task Memory и RetrievalPolicy.

Не сбрасывать их при добавлении файлов.

Не выполнять скрытый поиск
за пределами выбранного набора.

==================================================
6. OTHER SOURCE SCOPES
==================================================

Если новый документ
появился в другом источнике,
не предлагать добавить его
в текущий ограниченный набор.

Для других источников сохранить
ранее согласованное общее уведомление,
без дублирования.

Если выбраны:

"Все документы"
или весь конкретный источник,

новые INDEXED документы уже
доступны по динамической области поиска.

Не предлагать повторно включать то,
что и так входит в scope.

==================================================
7. EVENT DELIVERY
==================================================

Использовать существующие
SSE/HTMX/polling.

Не запускать MCP scan
при открытии Chat.

Для новых файлов активного источника
показывать встроенное предложение
без перезагрузки страницы.

Не терять событие,
если Chat был закрыт:
при открытии сверить сохраненные
нерассмотренные события с текущим scope.

После "Не сейчас" не повторять
то же предложение при следующем
неизменном сканировании.

Учитывать source ID, document ID
и version/fingerprint.

==================================================
8. UI
==================================================

Показывать компактную панель
сразу под выбором области анализа.

Например:

Найдены новые документы — 3

Агентский договор.docx   INDEXED
Допсоглашение.pdf       INDEXED
Отчёт агента.docx       PROCESSING

[Добавить 2 документа] [Не сейчас]

Не создавать:

- новую вкладку;
- отдельную страницу;
- дерево файлов;
- файловый менеджер;
- постоянную боковую колонку.

Панель должна исчезать
после решения пользователя.

==================================================
9. TESTS
==================================================

A. Новый файл текущего источника
   автоматически появляется в Chat.

B. Новый файл другого источника
   не предлагается для добавления.

C. PROCESSING не добавляется
   в выбранный набор.

D. INDEXED добавляется
   только после подтверждения.

E. Новый документ не дублируется.

F. Выбор сохраняется в ChatSession.

G. Point RAG и Exhaustive
   используют обновленный scope.

H. Остальные ограничения
   RetrievalPolicy сохраняются.

I. "Не сейчас" не меняет scope.

J. Повторный scan UNCHANGED
   не создает повторное предложение.

K. Один event не вызывает
   одновременно toast и inline notice.

L. Для всего корпуса
   не появляется ненужное предложение.

M. Existing Chat/RAG/ingestion
   продолжают работать.

==================================================
10. REAL E2E
==================================================

Проверить:

1. В Chat выбраны 16 документов
   конкретного источника.

2. В этот источник добавлен новый DOCX
   в разрешенной тестовой папке.

3. MCP обнаруживает его автоматически.

4. Ingestion/indexing завершается.

5. Chat без действий пользователя
   показывает название нового документа.

6. Пользователь подтверждает добавление.

7. Счетчик становится 17.

8. Вопрос по новому документу
   дает ответ с подтверждающей цитатой.

9. Другие ChatSession не изменяются.

Не считать MOCK доказательством
реального SMB E2E.
