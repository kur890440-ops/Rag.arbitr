# Day 25 · Chat Diagnostic Export

1. **Файлы.** Добавлены `application/chat_diagnostic.py`, `application/diagnostic_trace.py`, `tests/test_chat_diagnostic.py`, `scripts/check_day25_diagnostic_ui.py`, этот отчёт. Изменены `web/chat.py`, `web/templates/chat.html`, `web/templates/chat_thread.html`, `web/static/chat.js`, `web/static/chat.css`, README. В `application/chat.py`, `dialogue.py`, `query_rewrite.py`, `rag.py` и `vectorstore.py` добавлены только точки наблюдения. Остальные изменения рабочего дерева существовали до этой задачи.
2. **ChatDiagnosticService.** `build(session_id, focused_turn_id=None)` читает согласованный SQLite snapshot в транзакции, выбирает связанные с сессией записи, собирает секции Markdown по явному списку полей и очищает секреты. Не вызывает `ChatSessionService.load`, который может восстанавливать и записывать контекст; экспорт сам не меняет БД, не вызывает LLM, embeddings, Qdrant или reranker. Один GET `/api/chat/sessions/{sid}/diagnostic`.
3. **Существовавшие trace fields.** TaskState before/after/patch, DialogueWorkingContext before, reference result и canonical prior claims, QuestionIntent, RetrievalPolicy и её policy filter, queries/rewrite, reference search mapping/verdicts, candidates, final sources, grounding, stage checkpoints. В comparison уже были raw candidates, cleanup, rerank scores, expanded context metadata, selected source text, claims/citations, generation settings и timings.
4. **Добавленные поля.** `ChatTurn.trace.diagnostic_events`: фактический input payload и system/user text resolver/router/reference verifier, аргументы и output contextual builder, actual Qdrant collection/limit/query_filter (без vector), rewrite guard input/proposed query/new tokens/decision, реальные generation request/result. Также `trace.max_reference_claims` и `trace.code_version`. Сбор событий привязан к ContextVar одного execute; после выхода восстанавливается, не разделяется между чатами. Ошибка capture не меняет решение pipeline.
5. **Reference trace.** `chat_turns.data.trace.reference_resolution_json`, `dialogue_context_before`, `reference_prior_claims`, новые `diagnostic_events` с `DAY25_REFERENCES`. Старые входы, которых нет в snapshot, обозначаются NOT RECORDED, а не восстанавливаются по текущему коду.
6. **Retrieval trace.** `rag_comparison_runs.data`: `retrieved_sources`, `dedup_diagnostics`, `candidate_trace`, `context_candidate_metadata_json`, `sources`. В ChatTurn сохраняются policy и reference mapping; новый event `qdrant_search` содержит именно filter, переданный в `query_points`, включая документные и активные chunk-ID ограничения.
7. **Grounding trace.** `rag_comparison_runs.data`: `grounding_result`, `grounding_diagnostics`, `claims_json`, `citations_json`, `refusal_reason`, `repair_used`; часть продублирована в ChatTurn. Цитаты и support scores экспортируются из сохранённых записей.
8. **Focused turn.** Общая кнопка выбирает последний завершившийся ход с assistant message, включая отказ/ошибку; RUNNING/QUEUED пропускаются. Пустой чат поддержан. Turn-кнопка передаёт точный `turn_id`; чужой turn или неизвестная сессия дают 404. История: последние 15 ходов плюс выбранный ход и исходные ходы его grounded referents, если они старше.
9. **Copy.** Внизу панели — «Скопировать диагностику»; у каждого assistant turn — кнопка внутри «Диагностика ответа и памяти». Frontend получает plain text из одного endpoint, вызывает `navigator.clipboard.writeText`, сообщает «Диагностика скопирована. Её можно вставить в ChatGPT.» без alert. Если Clipboard API недоступен на внешнем HTTP-интерфейсе, используется выделенный textarea + `execCommand('copy')`; при отказе остаётся выделенное поле для Ctrl+C, ложный success не показывается.
10. **Download.** Ссылка «Скачать .md», тот же endpoint с `download=true`, attachment `chat-diagnostic.md`. Ответы `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`.
11. **Redaction.** Отбор полей исключает config snapshots, полный корпус, индексы, embeddings и БД. Рекурсивная очистка sensitive keys; маскирование значений настроенного LLM key, секретных environment и локального `.env`, auth/cookie строк, Bearer, credential URLs, secret assignments/query parameters, sk/JWT форматов. Очистка применяется ко всем секциям, включая историю, названия, raw output и ошибки. Текст источников и персональные сведения документов намеренно не обезличиваются: это запрошенная диагностика, не публикация. Безусловно распознать произвольный неизвестный секрет без имени/формата невозможно; неизвестные config/auth поля не экспортируются.
12. **Security tests.** Синтетические MINIMAX_API_KEY, OPENROUTER_API_KEY, local config SecretStr, `.env` DB_PASSWORD, Authorization/Bearer/Basic, Cookie, nested JSON, credential URL и password assignments. Проверяется отсутствие значений и ключевых auth labels в результате. Также проверена изоляция чужого turn и read-only поведение экспорта.
13. **Структура.** SESSION → CHAT HISTORY → FOCUSED TURN → TASK STATE / CHANGE → DIALOGUE WORKING CONTEXT → PRIOR GROUNDED CLAIMS → REFERENCE RESOLUTION / INPUTS → CONTEXTUAL QUERY BUILDER → QUESTION INTENT → RETRIEVAL POLICY → ELIGIBLE DOCUMENTS → QUERY PIPELINE / GUARD → REFERENCE-AWARE RETRIEVAL → VECTOR RETRIEVAL → RAW CANDIDATES → HEURISTIC CLEANUP → RERANKING → CONTEXT EXPANSION → FINAL CONTEXTS → LLM GENERATION / ACTUAL REQUESTS / RESULT → GROUNDING / CLAIMS / CITATIONS → INSUFFICIENT CONTEXT DIAGNOSIS → ERRORS → TIMINGS → COMPONENTS → CODE VERSION. Значения — читаемые подписанные поля; вложенные структуры представлены JSON-блоками внутри Markdown.
14. **Functional test.** Выполнен локальный integration Q1 → court-only → exclude complaints → Q4 со scripted LLM и реальным application orchestration. Q4 INSUFFICIENT_CONTEXT; report содержит исходные Q1/Q4, прежний claim, resolver payload, actual filter, queries, candidates/contexts и MODEL_INSUFFICIENT_CONTEXT. Экспорт не изменяет session state. Это тест наблюдаемости, не новая проверка качества ответа внешней модели.
15. **Prior claim texts.** Да: canonical comparison claims загружаются только по referents из сохранённого working context этого хода, с проверкой принадлежности source turn той же сессии. Выводятся текст, qualified ID, source turn, support status/scores и число цитат.
16. **Actual resolved query.** Да: ChatTurn.resolved_question, сохранённый resolution и result resolver; новые builder inputs/outputs записываются непосредственно при вызове.
17. **Actual rewritten query.** Да: сохранённый rewrite result; дополнительно новые guard events сохраняют предложенную строку до fallback и новые lexical tokens. Для старого отвергнутого rewrite исходная строка NOT RECORDED, не выдумывается.
18. **Actual Qdrant filter.** Для новых ходов да, записан на границе `query_points`, тест это проверяет. Для исторических ходов есть прежний policy filter; полный составной Qdrant filter до добавления записи — NOT RECORDED. Эти два объекта явно различаются.
19. **Before/after rerank.** Да: raw candidates с preview до 400 символов и candidate trace с исходным/новым rank, scores, accepted/filter_reason. Для длинного списка показаны первые 20 и общий размер; итоговые contexts не урезаются. Cleanup diagnostics выводятся отдельно.
20. **Exact final contexts.** Сохранённые selected source fragments выводятся полностью, с provenance. Для новых POINT запросов также записаны точные system/user поля реального LLMRequest, включая grounding contract и repair, либо structured reference-verifier request. Selected context не выдаётся за доказанный сетевой payload исторического запроса: фактический старый request — NOT RECORDED. Полные normalized страницы EXHAUSTIVE не экспортируются, чтобы не превращать диагностику в corpus dump.
21. **Algorithms.** Resolver/query/policy/routing/retrieval/reranker/grounding решения, prompts, thresholds и generation settings не менялись. Новые точки только наблюдают; полный корпус повторно не обрабатывался, внешний LLM для этой задачи не вызывался.
