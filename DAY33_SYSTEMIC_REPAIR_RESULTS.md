## 2. Контракты данных

Расширены существующие `SourceUnit`, `Finding`, `ContractFact`, `GroundedClaim`, `Citation`, `ConsultIntent`, `BatchExtractionResult`. Используется существующий `DialogueWorkingContext`; второй памяти или RAG нет.

`Finding` сохраняет fact ID, документ, версию, блок, смещение, исходный текст, поля subject/predicate/object/role, статус проверки. `ContractCondition` описывает условие, значение, единицу, основание отсчёта и применимую роль. Числовое условие без значения/единицы не участвует в сравнении. `Citation.parts` представляет набор исходных фрагментов, а не выдуманную непрерывную цитату.

Для полей названия допустимо только восстановление буквального исходного значения при различиях пробелов/кавычек. Буквы, числа и порядок символов не исправляются. Источники и цитаты остаются неизменными; смысл и роль проверяются отдельно.

## 12. Grounding и причины отказов

Канонические блоки, версии и смещения проверяются отдельно от семантической связи вопрос–утверждение–источник. Результат офлайн-сверки сохранённых evidence spans; содержательная проверка Q4 не состоялась:

```json
{
  "Q1": {
    "spans": 44,
    "invalid": []
  },
  "Q2": {
    "spans": 53,
    "invalid": []
  },
  "Q3": {
    "spans": 95,
    "invalid": []
  },
  "Q4": {
    "status": "NOT_RUN",
    "reason": "HTTP_409; late Q3 record mislabeled by observer"
  }
}
```

Для Q3 сверены сохранённые промежуточные evidence, а не опубликованный ответ: HTTP 504. Файл `Q4-record.json` содержит поздно завершившийся Q3 (проверено поле question_text), а не результат Q4. `outcomes.json` для Q3/Q4 содержит устаревшую диагностическую секцию Q2, поскольку observer брал последний успешный diagnostic. Эти секции исключены из итоговых чисел; calls/tokens пересчитаны по provider-calls.json, HTTP — по response. Это отдельное ограничение диагностического стенда.

Эта проверка не является независимой юридической или семантической экспертизой каждого ответа. Semantic review выполнялся существующим EvidenceReview через реального провайдера. Известные причины отказов: `UNSUPPORTED_CONTRACT_FIELD`, `OUTPUT_LIMIT`, `EVIDENCE_REVIEW_INVALID_RESPONSE`, `UNSUPPORTED_RELATION`; причины не подменяются отсутствием фактов в документе.

Служебный coverage формирует приложение. Синтез проверяется по утверждениям и полному выбранному набору доказательств; независимо проверенные map facts сохраняются. Нет разрешения публиковать неподтверждённые поля или смешивать версии ради полноты.

## 13. Контекст и разрешения

Запросы Q1–Q4 отправлены в одной ChatSession (Q4 отклонён до обработки): `True`. Число сохранённых CONTRACT anchors после каждого вопроса: Q1=4, Q2=4, Q3=4, Q4=4.

Бюджет истории больше не удаляет verified WorkingContext; сохраняется вопрос последней пары, ограничивается текст ответа. Проекция для router компактная, без второй памяти. Но Q3 демонстрирует, что сохранение anchors и их правильное применение — разные проверки: данные остались, роутер их обошёл. Поэтому D5/D6 нельзя объявить полностью закрытыми.

Auth/ACL regression tests пройдены. Ссылки проверялись по одному источнику на документ, остальные цитаты — по содержимому офлайн. Это не утверждение о проверке каждого URL в браузере. Отсутствует разрешение расширять область за пределы source grants; код RetrievalPolicy и ingestion/MCP не заменялись.

## 16. Оставшиеся дефекты и границы результата

1. Нестабильное извлечение обязательного имени: модель достраивает отсутствующее слово. Нужен ограниченный протокол исправления конкретного поля с новым выбором канонических фрагментов, без нечёткого исправления имён.
2. `OUTPUT_LIMIT` у extraction и review; текущая оценка выходного бюджета не гарантирует вместимость ответа. Нужна проверенная разбивка/ограниченный recovery без потери уже подтверждённых элементов.
3. Router принимает необоснованный `NEW_SUBJECT` без явно указанного нового объекта. Нужна проверяемая связь классификации с текстом текущего вопроса и контекстом, без списков фамилий.
4. Q2 не охватывает все пять сторон; Q3 сравнивает неправильную область. Матрица и семантическая проверка сами по себе эти дефекты не исправляют.
5. Поля роли/типа условия всё ещё допускают свободные строки (`agent`/`Агент`, `subagent`/`субагент`, `other precise type`); это разделяет эквивалентные группы и мешает надёжной матрице. Нужен валидируемый единый словарь ролей и типов с сохранением исходного значения.
6. После таймаута Q3 следующий запрос получил BUSY; успешного финального Q4 нет. Observer не должен присваивать позднему результату ID следующего вопроса или повторять последнюю успешную диагностику.
7. Стоимость и задержка выросли; оптимизация не может достигаться ослаблением доказательств.
8. Рабочий сервис не перезапущен с непрошедшей приёмку версией. Браузер и LAN smoke после deployment — NOT RUN. Изменения доступны для ревью в рабочем дереве.
