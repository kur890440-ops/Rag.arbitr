ЗАДАЧА

Реализовать управление пользователями
и авторизацию через Telegram
для существующего /consult.

Сохранить MiniMax и существующий RAG.

==================================================
1. ОБЯЗАТЕЛЬНЫЙ СЦЕНАРИЙ
==================================================

Пользователь:

1. Открывает Telegram-бота.
2. Отправляет /start.
3. Получает статус ожидания.
4. Администратор одобряет заявку.
5. Пользователь получает сообщение.
6. Открывает /consult.
7. Получает одноразовый код.
8. Отправляет /login CODE в Telegram.
9. Автоматически авторизуется.
10. Общается с MiniMax по документам.

При блокировке пользователя
доступ к /consult прекращается.

==================================================
2. INSPECT FIRST
==================================================

Исследуй:

- existing /consult routes;
- anonymous ChatSession;
- SQLite storage;
- existing authentication mechanisms;
- internal admin UI;
- configuration;
- session handling;
- current MiniMax/RAG integration;
- available Telegram integrations.

Не переносить автоматически код
из отдельного WORKSHOP_AGENT.

Если подходящих компонентов нет,
создать минимальные внутри rag.арбитр.

==================================================
3. TELEGRAM BOT
==================================================

Подключить Telegram Bot API.

Использовать отдельный bot token
для rag.арбитр.

Поддержать:

/start
/login CODE
/status

Использовать один экземпляр
бота и корректный lifecycle.

Выбрать polling/webhook
с учетом существующего deployment.

Не запускать второй самостоятельный
Telegram backend без необходимости.

==================================================

==================================================
5. ADMIN BOOTSTRAP
==================================================

Предусмотреть явную настройку

пользователю автоматически.

Не позволять удалить или заблокировать
последнего действующего администратора.

==================================================
6. REGISTRATION
==================================================

При /start:

- найти пользователя по Telegram ID;
- если отсутствует — создать PENDING;
- не дублировать заявки;
- показать текущий статус.

При одобрении:

PENDING → ACTIVE.

Отправить пользователю
уведомление через Telegram.

При BLOCKED:
авторизация запрещена.

==================================================
7. LOGIN CODE
==================================================

В /consult показывать
одноразовый код.

Использовать:

crypto-secure generation
code hash storage
TTL 120 seconds
browser nonce binding
attempt limit
rate limiting
single-use consumption.

После команды /login CODE
проверять Telegram identity
и статус ACTIVE.

Нельзя авторизовать браузер
только по знанию Telegram ID.

==================================================
8. WEB SESSION
==================================================

Создать серверную session,
используя существующий storage.

Cookie:

HttpOnly
Secure
SameSite
Path
expiration.

Token хранить в БД
только в виде hash.

При logout:
revoke session.

При BLOCKED:
отозвать все активные sessions.

Права пользователя проверять
на сервере при каждом запросе.

17. REAL E2E
==================================================

Проверить полный сценарий:

Telegram /start
→ PENDING
→ одобрение в Admin UI
→ уведомление Telegram
→ /consult
→ login code
→ /login CODE
→ authenticated Chat
→ реальный вопрос MiniMax
→ ответ с цитатой.

BLOCK USER
→ активный Chat теряет доступ.

не включать в демонстрационные логи.

Если Telegram или MiniMax недоступны,
отдельно отметить NOT RUN.
